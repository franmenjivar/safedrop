# Note on this repository's history

The original working tree of this project was deleted before it was ever
committed to version control. What is published here was rebuilt by replaying
the complete, ordered sequence of file writes recorded in the development
session logs: 89 whole-file writes, 8 appends, 112 in-place patches and 2
renames, applied in their original chronological order.

This note records what that reconstruction does and does not guarantee, so that
nobody — including the author — mistakes a rebuilt file for a verified one.

## What is known good

- **All 57 Python modules compile**, and the package imports cleanly.
- **The test suite collects all 9 tests** documented in `REPRODUCE.md`, which is
  the count the original project reported.
- Every source file is the last version that appears in the session logs. No
  file was reconstructed from memory, inference or paraphrase; each is a
  verbatim replay of the bytes that were written at the time.

## What was lost and regenerated

`data/geo_cache/*.geojson` was committed in the original project specifically so
that the benchmark would stay offline and reproducible. That cache was lost with
the working tree. The files here were re-fetched from OpenStreetMap on
2026-09-13 by `scripts/fetch_real_geometry.py`.

**OpenStreetMap has changed since the original fetch.** Four features that the
scenario definitions pin by name no longer survive `scripts/verify_anchors`:

| Feature | Region |
|---|---|
| `Little Stacy` | `central_austin` |
| `Jester Farms Park` | `round_rock` |
| `HACA Parking` | `central_austin` |
| `Chandler Creek Park` | `round_rock` |

Because of that, **8 of the 15 benchmark scenarios build; 7 do not**
(`scenario_17`, `scenario_18`, `scenario_20`, `scenario_22`, `scenario_23`,
`scenario_24`, and one other in `scripts/build_fixtures.py`).

The anchors were deliberately **not** substituted with nearby alternatives.
Swapping in a different park would silently change the benchmark the reported
results were measured on, and any number produced that way would not be
comparable to the numbers in `README.md` and `REPRODUCE.md`.

## One class of defect to watch for

Most of the replayed patches edit files with `str.replace()`, which does nothing
and raises nothing when its anchor text does not match. A patch whose anchor had
already drifted therefore applied *silently as a no-op* rather than failing.

One such gap has been found and repaired: `AgentConfig.mode` was never added to
`app/config.py`, because the patch that introduced it anchored on
`model: str = "google:gemini-2.5-flash"` while the file already read
`google-gla:`. Without it the console would not start at all. The field was
restored exactly as the session log specifies.

The whole test suite and an end-to-end console run both pass now, but that class
of silent divergence cannot be ruled out in code paths neither exercises.

## Consequence for the reported results

**The result tables in `README.md` and `REPRODUCE.md` cannot currently be
reproduced end to end from this repository.** They were measured against the
original geometry cache, which no longer exists. Treat them as a record of what
the system scored at the time, not as a claim this checkout will reproduce.

To restore full reproducibility, one of the following is needed:

1. the original `data/geo_cache/` contents, if a copy is ever recovered; or
2. re-pinning the four anchors to currently-verifiable features and **re-running
   the whole benchmark**, publishing the new numbers as a new measurement.

## Not recovered

- `results/` and `trajectories/` — gitignored in the original project, and
  regenerated by `evaluation/run_all.py`.
- The project's git history. This repository starts from a single commit.
